# 给 Gemini 的前端美化交接

## 任务目标

在本仓库改进**独立文件库**和 **Luker 文件库插件**的视觉设计与交互呈现。只做前端美化：布局、间距、排版、颜色、响应式、可访问性、加载/空状态及按钮层级。保持现有功能、权限、请求与数据流不变。先在本地提交可审查的代码和前后对比截图，不直接改生产主机或发布版本。

仓库：`https://github.com/kj1534/luker-video-toolkit`。本机工作目录：`/home/accx/codex-workspace/luker-video-toolkit`。从最新 `main` 开始，先检查工作树与现有改动，保留他人改动。Luker 核心项目不在本任务范围，所有改动留在此插件仓库。

## 页面和代码位置

| 范围 | 主要文件 | 用途与注意点 |
|---|---|---|
| 独立文件库外壳 | `app/public/index.html`、`app/public/app.css` | 登录页、顶栏、全局布局、弹窗外观和移动端样式。 |
| 独立文件库页面 | `app/public/app.js` | 账号、插件令牌、用户管理、节点与策略界面。只改呈现，不改其 API 调用和状态处理。登录密码入口已放在“用户管理”；令牌签发与撤销在“插件令牌”。 |
| 两端共用文件库 | `library-ui.js`、`style.css` | 文件列表、预览、上传、链接导入、任务、设置；改共用组件会同时影响独立应用和 Luker。 |
| Luker 插件入口 | `index.js`、`manifest.json` | 附件菜单只有一个“文件库”入口；连接令牌、加文件链接、上传和附加均从该入口进入。可改入口和面板的视觉呈现，不改本轮附件逻辑。 |
| 设置表单 | `settings.js` | 可调整表单分组与样式；保留字段名、校验和提交格式。 |

`app/main.mjs`、`app/auth.mjs`、`server/`、`node/`、`media.js`、`upload.js` 属于服务、权限或传输逻辑。前端美化不需要改这些文件。私有部署目录、凭据文件、备份和线上配置也不属于工作区。

## 必须保持的行为

- 独立应用和 Luker 使用同一文件库能力，但登录机制不同：独立应用用账号会话，Luker 服务端保存每用户插件令牌。令牌仅显示一次；不要把令牌、GCS 凭据或节点控制信息放进页面、日志、截图或仓库。
- Luker 附件菜单只注册一个“文件库”入口；连接或更换账号、直接添加文件链接、上传、链接导入、文件列表和任务仍可从这里到达。不要增加多个平行入口。
- 保留当前上传方式、分片续传、任务轮询/取消/重试、文件分页/筛选、预览/下载/复制/删除确认和权限错误提示。视觉重排不得重新提交任务或丢失续传状态。
- 文件默认只附加到当前轮；重新生成可用该轮附件，下一轮不自动重发。保留与原生文本/图片附件混用、流式响应和模型选择。
- `accx` 对旧 `default-user` 对象的访问是服务端私有授权。不要在前端实现用户前缀判断、改 URI、复制对象，或把所有用户的文件合并展示。
- 改文案时保持按钮行为和风险说明对应：GCS 预览/下载可能先复制到 copyparty，删除只删所选存储中的一份，较大附件可能先生成 GCS 副本。
